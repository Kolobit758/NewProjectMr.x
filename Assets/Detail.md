1. ระบบฟาร์ม (ลากวาง & ความสมจริงเรื่องปุ๋ย/น้ำ/ขาย)
ปัจจุบันระบบฟาร์มใช้การคลิกเมาส์เพื่อทำงาน และรับปุ๋ย/น้ำเป็นรอบๆ ตามสถานะ CropStage

ไฟล์หลักที่ใช้ทำงานในตอนนี้:



FarmingManager.cs
 : จัดการตอนผู้เล่นคลิกเมาส์
TryInteractWithPlot() : เช็คว่าคลิกโดนแปลงไหม และถือเมล็ดอยู่หรือเปล่า ถ้าใช่ก็ปลูก


CropPlots.cs
 : ตัวเก็บข้อมูลของแปลงนั้นๆ
Update() : นับเวลาโต (growthTimer) และตะโกนเรียกยูนิตมารดน้ำอัตโนมัติ (CallNearbyIdleUnitForWater())
OnUnitInteract() : จัดการสถานะเวลา Unit วิ่งมาถึงแปลง (มาส่งปุ๋ย ส่งน้ำ หรือเก็บเกี่ยว)
ตัวแปรที่มีอยู่แล้ว: currentSoilNutrients (ธาตุอาหาร), appliedFertilizer
🛠️ ไฟล์ที่ต้องแก้เพื่อให้ได้ตามไอเดีย:

ระบบลากวาง: ต้องไปแก้ 

FarmingManager.cs
 (หรือสร้าง UIInventoryDragDrop.cs ใหม่) เปลี่ยนจากการกดเมาส์คลิก Input.GetMouseButtonDown(0) ไปเป็นใช้ Event System ของ UI (เช่น IBeginDragHandler, IDropHandler) เวลาลากเมล็ดจากช่อง UI มาปล่อยบนจอ ค่อยยิง Raycast ลงไปหา CropPlot
ความสมจริง ปุ๋ย/น้ำ (ค่อยๆ ลด): ต้องแก้ที่ 

CropPlots.cs
 ใน Update() แทนที่จะรอรับปุ๋ย 1 ครั้ง ให้ทำเป็นหลอดความชื้น/แร่ธาตุ ที่ค่อยๆ ลดลงตามเวลา (Time.deltaTime) ถ้าน้ำแห้งก็หยุดโตหรือตาย และเอาตัวแปร currentSoilNutrients มาคำนวณผลผลิต
การขาย: หลัง HarvestCrop() ใน 

CropPlots.cs
 จะต้องส่ง Event โยนทรัพยากรเข้าคลัง และสร้างระบบ Economy มารับซื้อ
2. ระบบ Auto (คลิกยูนิต -> แถบคำสั่งเหมือนแถบสกิล -> ตั้งค่าปล่อย Auto)
ปัจจุบันยูนิตมีความฉลาดระดับนึง (Idle แล้วสแกนหาของทำต่อ) แต่มันยังถูก Hardcode ไว้ใน JobType ว่าให้ทำ Gathering หรือ Farming

ไฟล์หลักที่ใช้ทำงานในตอนนี้:



UnitBase.cs
 : ควบคุมพฤติกรรมทั้งหมดผ่าน State Machine
RunStateMachine() : ตัวคุมหัวใจหลักของยูนิต
HandleIdleState() : ตอนที่ยูนิตว่าง มันจะเช็ค currentJobType ถ้าตั้งเป็น Farming มันก็จะไปทำ CommandFarmingPatrol() หรือถ้าเป็น Gathering มันก็จะสแกนต้นไม้แถวนั้น
🛠️ ไฟล์ที่ต้องแก้เพื่อให้ได้ตามไอเดีย:

UI แถบคำสั่ง: ต้องสร้าง UI ใหม่ (เช่น UnitCommandPanel) ที่โผล่ขึ้นมาตอนกดเลือก Unit ระบบนี้จะไปอ่านข้อมูลจาก 

UnitBase.cs
 ว่าตัวที่เลือกมีสกิลหรือรับคำสั่งอะไรได้บ้าง
คิวคำสั่งอัตโนมัติ: ใน 

UnitBase.cs
 ต้องเปลี่ยนจากตัวแปร JobType แบบตัวเดียว เป็น "ระบบ Queue คำสั่ง" (เช่น List<AutoTask>)
เวลาผู้เล่นกดปุ่มบนแถบคำสั่ง ให้ส่งค่ามาเก็บใน List นี้
ใน HandleIdleState() แทนที่จะเดาเอง ให้มันไปดึงคำสั่งที่ผู้เล่นตั้งไว้ใน List มาทำเรื่อยๆ วนลูปไปครับ
3. ระบบ Combat ให้ดู "ว้าวววว"
ตอนนี้ยูนิตเวลาสู้มันยังทื่อๆ วิ่งไปชน ฟาด จบ อยากให้มันมีความเป็นสงคราม หรือดูฉลาดขึ้น มี Tactic

ไฟล์หลักที่ใช้ทำงานในตอนนี้:



RTS_movement.cs
 :
MoveSelectedUnits() : เวลาลากคลุมแล้วคลิกขวา มันสั่งให้ทุกตัวเดินไปที่ hit.point ทื่อๆ ทับไลน์กัน


UnitBase.cs
 :
HandleIdleState() : มีการแอบสแกนหาศัตรูใกล้ๆ (TryFindNearbyEnemy)
HandleCombatBehavior() : (State การตี) ตอนนี้ทำแค่เช็คระยะ attackRange ติด Cooldown แล้วหักลบเลือด
มีตัวแปร unitFaction เตรียมไว้ทำเป่ายิ้งฉุบ (แพ้ทาง/ชนะทาง) อยู่แล้ว
🛠️ ไฟล์ที่ต้องแก้เพื่อให้ได้ตามไอเดีย (Wow Factor):

Formation Movement (เดินจัดรูปขบวน): ใน 

RTS_movement.cs
 ฟังก์ชัน MoveSelectedUnits() แทนที่จะส่งเป้าหมายเดียวกันให้ทุกตัว ให้คำนวณ Grid หรือวงกลมรอบๆ จุดคลิก (Offset) เพื่อให้มันจัดแถวหน้ากระดาน เดินเข้าตีสวยๆ ไม่ขี่คอกัน
สเต็ปการต่อสู้ (Dodging, Skills, Impact): ไปเสริมที่ 

UnitBase.cs
 ใน HandleCombatBehavior()
เพิ่ม State ชาร์จตีก่อนฟัน (Windup)
เพิ่ม Animation พิเศษเมื่อคริติคอล หรือมีการกระเด็น (Knockback effect)
ดึง unitFaction (แพ้ทาง) มาเพิ่ม Effect หรือ Particle อลังการเวลาโจมตีตัวที่มันชนะทาง
ระบบคำสั่งพิเศษระหว่างสู้: จากข้อ 2 (แถบคำสั่ง) สามารถใส่ปุ่มสกิลพิเศษ เช่น "สั่งพุ่งชน", "สั่งกลายร่าง" ให้ผู้เล่นกดตอนต่อสู้ได้เลยครับ
